Projeto explicado passo a passo

Um Arduino, três sistemas e uma ideia simples

Todo o projeto repete o mesmo ciclo, milhares de vezes por segundo: ler os sensores, decidir e agir.

  1. 1. Ler

    • HC-SR04: distância
    • Sensor de luz: feixe do laser
    • Sensor de chuva: água na placa

  2. 2. Decidir

    • Tem alguém a até 25 cm?
    • O feixe foi obstruído?
    • A placa está molhada?

  3. 3. Agir

    • Servo: abre ou fecha a tampa
    • Buzzer: apita de forma intermitente

Segurança: nunca olhe para o feixe do laser nem o aponte para os olhos de alguém ou para superfícies que reflitam.

    Duas ideias centrais
    
      
    Por que o programa usa um filtro
    
      
    Sensores reais tremem. Uma gota pode fazer o sinal oscilar várias vezes. O filtro só aceita uma mudança que fique estável por um tempo.
    

      
    
        
        
    
          
          
    
            
            
          
    
          
    Alarmes disparados: 0
    
        
    
        
    Segure o botão por 2 segundos com o filtro em 500 ms: um alarme só. Depois, coloque o filtro em 0 ms e repita: cada tremida vira um alarme.
    
      
    

      
    Por que o programa não usa delay()
    
      
    O Arduino faz uma coisa de cada vez. Se ele parar para esperar, ninguém lê os sensores nesse tempo.
    
      
    
        
    
          
    Com delay()
    
          
    digitalWrite(pinoBuzzer, LOW);
delay(200);   // parado: nao le nada
digitalWrite(pinoBuzzer, HIGH);
delay(200);   // parado de novo
    
          
    Durante o apito, a tampa não abriria e o programa não veria o feixe voltar.
    
        
    
        
    
          
    Com millis()
    
          
    unsigned long agora = millis();
if (agora - ultimaTrocaBip >= intervaloBip) {
  ultimaTrocaBip = agora;
  definirBuzzer(!buzzerApitando);
}
    
          
    O programa só olha o relógio e segue em frente. Nada trava, e os três sistemas parecem rodar ao mesmo tempo.
    
        
    
      
    
    
    

    
    
      
    Caso real da bancada
    
      
    O sensor que apagava depois do reset
    
      
    Este defeito aconteceu de verdade neste projeto. É um bom exemplo de como investigar um problema, um teste de cada vez.
    
      
      
        
    1. Sintoma
      O sensor de luz acendia no reset e apagava cerca de 1 segundo depois. O buzzer tocava mesmo com o laser em cima do sensor.
      2. 
        
    2. Primeiro suspeito
      Falta de energia por causa do servo. O servo foi desligado, e o problema continuou.
      3. 
        
    3. Isolando o problema
      Os fios dos pinos 7 e 12 foram retirados, e o sensor continuou apagando. Laser e buzzer saíram da lista de suspeitos.
      4. 
        
    4. A pista
      Apertar o reset não corta o pino 5V. Um sensor bem alimentado nem perceberia o reset. Se ele reagia, a ligação de alimentação estava errada.
      5. 
        
    5. Solução
      O fio GND do sensor saiu da fileira digital, onde ele fica colado no pino 13 e no AREF, e foi para os GND da fileira POWER. Funcionou.
      6. 
      
    
      
    Lição: mude uma coisa de cada vez e observe. Às vezes o defeito não está no programa, e sim em um fio um furo ao lado.
